HNSW 온라인 갱신 연산의 의사코드와 그림

삽입, 삭제, 값 갱신, 삭제 슬롯 재사용 네 가지 연산을 hnswlib 구현 기준으로 설명합니다. 의사코드는 실제 코드에서 잠금과 예외 처리를 걷어낸 형태이고, 그림은 같은 작은 그래프 위에서 각 연산이 무엇을 바꾸는지 보여 줍니다.

삽입은 레코드 전체를 새로 씁니다. 삭제는 flag만, 값 갱신은 vector와 nbr를, 슬롯 재사용은 flag·vector·label·nbr를 바꿉니다.

1. 삽입 addPointWithLevel · mutuallyConnectNewElement

새 노드의 최고 레벨을 무작위로 뽑은 뒤, 그 레벨보다 높은 계층에서는 탐욕 검색으로 진입점을 좁히고, 그 레벨부터 0계층까지는 빔 검색으로 후보를 모아 양방향 간선을 만듭니다.

addPoint(x, label):
    # label이 이미 있으면 삽입이 아니라 값 갱신으로 분기한다 (3절)
    if label in label_lookup: return updatePoint(x, label_lookup[label])

    c  = cur_element_count++                  # 내부 ID는 증가만 하는 일련번호
    lc = floor( −ln U(0,1) / ln M )           # P(lc ≥ l) = M^−l
    record[c] = { links: ∅, vector: x, label }
    ep = enterpoint

    # (1) 탐욕 하강: 새 노드가 없는 상위 계층
    for l = maxlevel down to lc+1:
        ep = greedy(x, ep, l)

    # (2) 계층별 연결: 새 노드가 존재하는 계층
    for l = min(lc, maxlevel) down to 0:
        W = searchLayer(x, ep, ef_construction, l)
        if deleted(enterpoint): W ∪= { enterpoint }        # 삭제된 진입점도 강제로 연결
        N = selectNeighbors(W, M)                        # 최대 M개
        links(c, l) = N
        for n in N:                                       # 역방향 간선
            if |links(n, l)| < Mmax(l):  links(n, l).append(c)
            else: links(n, l) = selectNeighbors(links(n, l) ∪ {c}, Mmax(l))   # 꽉 찼으면 재선택
        ep = nearest(N)                                   # 다음 계층의 진입점

    if lc > maxlevel: enterpoint = c; maxlevel = lc       # Mmax(0) = 2M, Mmax(l≥1) = M


greedy(x, ep, l):                                     # 후보 하나만 들고 내려가는 검색
    repeat until no change:
        for n in links(ep, l):
            if dist(x, n) < dist(x, ep): ep = n
    return ep

searchLayer(x, ep, ef, l):                             # 빔 검색. 검색 API도 0계층에서 이것을 쓴다
    C = {ep}; W = {ep}; visited = {ep}                    # C: 확장 후보(최소 힙), W: 결과(최대 힙, ≤ ef)
    while C ≠ ∅:
        c = C.pop_nearest()
        if dist(x, c) > max_dist(W) and |W| == ef: break
        for n in links(c, l):
            if n ∈ visited: continue
            visited ∪= {n}
            if |W| < ef or dist(x, n) < max_dist(W):
                C.push(n)                                 # 삭제된 노드도 확장은 한다
                if not deleted(n): W.push(n)              # 결과에는 넣지 않는다
                if |W| > ef: W.pop_farthest()
    return W

selectNeighbors(W, M):                                # 논문 Alg.4, extend/keepPruned 없음
    if |W| < M: return W                                  # M개 미만이면 가지치기 없음
    R = []
    for c in W sorted by dist(x, c):
        if |R| ≥ M: break
        if ∀ r ∈ R: dist(r, c) ≥ dist(x, c): R.append(c)  # 이미 고른 r이 c에 더 가까우면 c는 버림
    return R

주의할 점. 새 노드는 0계층에서도 처음에 M개까지만 연결하고 나머지 M개 자리는 이후 삽입되는 노드가 역방향 간선으로 채웁니다. 역방향 간선 재선택에서 q가 탈락하면 간선은 q → n 한 방향으로만 남습니다. 탈락한 기존 간선을 되살리는 keepPrunedConnections는 구현되어 있지 않아, 어떤 노드가 들어오는 간선을 모두 잃을 수도 있습니다.

2. 삭제 markDelete · 논리적 삭제

삭제는 그래프를 건드리지 않습니다. 레코드의 플래그 한 비트를 켜고 카운터를 올리는 것이 전부이며, 검색 쪽에서 그 노드를 결과에서만 걸러냅니다.

markDelete(label):
    id = label_lookup[label]                  # 매핑은 지우지 않는다
    flag(id) |= DELETE_MARK                   # 레코드의 세 번째 바이트, bit0
    num_deleted++
    if allow_replace_deleted: deleted_elements ∪= {id}    # 4절에서 재사용할 슬롯 집합
    # 간선, 벡터, 레벨, 진입점은 모두 그대로 둔다. 되돌리려면 unmarkDelete.

searchKnn(q, k):                                # 삭제가 검색에 미치는 영향
    ep = enterpoint                           # 진입점이 삭제돼도 교체하지 않는다
    for l = maxlevel down to 1: ep = greedy(q, ep, l)      # 삭제 여부를 보지 않는다
    if num_deleted == 0: W = searchLayer<bare>(q, ep, max(ef, k), 0)   # 삭제 확인을 컴파일 시점에 제거한 빠른 경로
    else:                W = searchLayer<checked>(q, ep, max(ef, k), 0) # 후보마다 flag 확인, 결과에서만 제외
    return k nearest of W

주의할 점. 삭제가 한 건이라도 생기면 모든 쿼리가 삭제 확인이 들어간 느린 경로로 바뀝니다. 삭제된 노드는 이웃의 차수 한 자리를 계속 차지하고, 메모리는 회수되지 않으며 cur_element_count도 줄지 않습니다. 물리 삭제와 압축은 없고, 메모리를 되찾는 유일한 수단은 4절의 슬롯 재사용입니다.

3. 값 갱신 updatePoint · repairConnectionsForUpdate

이미 있는 label로 addPoint를 호출하면 노드를 새로 만들지 않고 벡터를 덮어쓴 뒤 두 단계로 간선을 고칩니다. 먼저 갱신된 노드가 가리키던 이웃들이 자기 이웃 목록을 다시 고르고, 그다음 갱신된 노드를 새 위치에서 처음 삽입하듯 다시 연결합니다.

updatePoint(x_new, id):
    vector(id) = x_new                        # 잠금 없이 덮어쓴다. 동시 검색은 섞인 값을 읽을 수 있다

    # (1) 기존 이웃들의 간선 재선택. 레벨은 다시 뽑지 않고 그대로 둔다
    for l = 0 .. level(id):
        N1 = links(id, l)                     # id가 가리키는 1-hop 이웃만. id를 가리키기만 하는 노드는 모름
        C  = {id} ∪ N1 ∪ ⋃_{n ∈ N1} links(n, l)                # 2-hop 후보 집합 (최대 1+2M+4M² 개)
        for n in N1:
            K = C \ {n} 중 n에 가까운 min(ef_construction, |C|−1)개
            links(n, l) = selectNeighbors(K, Mmax(l))         # n의 리스트를 통째로 교체

    # (2) id를 새 위치에 다시 연결 (삽입의 (1)(2)단계와 같다)
    repairConnections(x_new, id)

repairConnections(x, id):
    ep = enterpoint
    for l = maxlevel down to level(id)+1: ep = greedy(x, ep, l)
    for l = level(id) down to 0:
        W = searchLayer(x, ep, ef_construction, l) \ {id}     # 자기 자신 제외 (self-loop 방지)
        if W == ∅: continue
        N = selectNeighbors(W, M)
        links(id, l) = N                                      # 덮어쓰기 (isUpdate=true)
        for n in N:
            if id ∈ links(n, l): continue                     # 이미 가리키면 건너뜀
            append or reselect as in insertion
        ep = nearest(N)

비용. M=16이면 0계층의 2-hop 후보가 최대 약 1,057개이고, 이웃 32개마다 이 후보 전체와 거리를 계산하므로 (1)단계만 약 3.4만 번의 거리 계산이 듭니다. 실험에서 값 갱신은 신규 삽입보다 점당 약 5배 느렸습니다. updateNeighborProbability를 1 미만으로 주면 재선택할 이웃을 표본으로 줄일 수 있지만, 라이브러리의 공개 API는 항상 1.0을 넘깁니다.

4. 삭제 슬롯 재사용 addPoint(…, replace_deleted=true)

생성자에서 allow_replace_deleted=true를 켰을 때만 동작합니다. 삭제된 노드의 슬롯을 하나 꺼내 label과 벡터를 새 점의 것으로 바꾼 뒤, 3절의 값 갱신을 그대로 실행합니다. 기존 레벨과 간선을 물려받으므로 그래프 수선도 값 갱신과 같습니다.

addPoint(x, label, replace_deleted=true):
    id = deleted_elements.pop_any()           # unordered_set::begin(). 비어 있으면 일반 삽입으로
    if id == none: return addPoint(x, label)

    old = label_of(id)
    label_of(id) = label                      # 레코드의 label 필드
    label_lookup.erase(old); label_lookup[label] = id
    flag(id) &= ~DELETE_MARK; num_deleted−−   # 삭제 표시 해제
    updatePoint(x, id)                        # 벡터 덮어쓰기 + (1) 이웃 재선택 + (2) 재연결
    # 잠금은 새 label 기준으로만 잡는다. 같은 순간 old label로 unmarkDelete를 부르면 경쟁 상태가 된다.

주의할 점. 어느 슬롯을 재사용할지는 해시 집합의 순서에 따라 정해지므로, 새 점과 전혀 무관한 위치의 슬롯을 받을 수 있습니다. 그 슬롯의 옛 이웃들이 새 점을 가리키는 단방향 간선이 남는 것은 값 갱신과 같은 한계입니다. 그래도 전체의 110%를 교체한 실험에서 recall@10은 ef≥50에서 새로 만든 인덱스와 0.002 이내였습니다.
