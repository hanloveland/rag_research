1부 · HNSW 기초

1. 풀려는 문제: 근사 최근접 이웃

벡터 집합 X = {x₁, …, x_N} ⊂ ℝ^d와 질의 벡터 q가 주어졌을 때, q와 가장 가까운 k개를 찾는 문제가 k-최근접 이웃(k-NN) 검색입니다. RAG에서는 N이 문서 청크 수(수백만~수십억), d가 임베딩 차원(384~3,072)입니다.

  • 정확 검색(brute force)은 거리를 N번 계산합니다. d=768, N=1억이면 질의 하나에 768억 번의 곱셈이 들어 실시간 서비스가 불가능합니다.
  • 트리(k-d tree 등)는 차원이 수십을 넘으면 가지치기가 거의 되지 않아 선형 탐색과 비슷해집니다. 이것이 차원의 저주입니다.
  • 근사 최근접 이웃(ANN)은 정답 k개 중 일부를 놓치는 것을 허용하는 대신 거리 계산을 수천 번 수준으로 줄입니다. 품질은 recall@k = |찾은 k개 ∩ 정답 k개| / k 로 잽니다.

HNSW는 ANN 방법 중 그래프 기반 방법에 속합니다. 데이터 포인트를 노드로, "가까운 점끼리"를 간선으로 잇는 근접 그래프를 미리 만들어 두고, 질의가 오면 그래프 위를 이동하며 답을 찾습니다. 거리 계산 횟수가 N이 아니라 대략 log N에 비례합니다.

2. 근접 그래프 위의 탐욕 검색

핵심 직관은 단순합니다. 지금 서 있는 노드의 이웃 중 q에 더 가까운 노드가 있으면 그리로 옮기고, 더 가까운 이웃이 없으면 멈춥니다. 이것이 탐욕 검색(greedy search)입니다. 그래프가 잘 만들어져 있다면 멈춘 노드가 q의 최근접 이웃이거나 그 근처입니다.

탐욕 검색이 제대로 동작하려면 그래프가 두 가지 성질을 가져야 합니다.

  1. 어디서 출발해도 목적지 근처에 도달해야 합니다(navigability). 이웃이 모두 한 방향으로만 몰려 있으면 반대쪽 영역으로는 갈 수 없습니다. Delaunay 그래프나 그 근사인 relative neighborhood graph(RNG)는 이 성질을 가집니다. 5절의 이웃 선택 휴리스틱이 RNG 조건을 근사합니다.
  2. 멀리 있는 노드로 건너뛰는 간선(long-range link)이 있어야 합니다. 가까운 이웃만 있으면 한 번에 한 걸음씩만 움직여 N에 비례하는 시간이 걸립니다. 긴 간선이 섞여 있어야 "작은 세상(small world)" 성질이 생기고 경로 길이가 log N 수준으로 줄어듭니다.

HNSW의 전신인 NSW(Navigable Small World)는 한 그래프 안에 긴 간선과 짧은 간선을 섞었습니다. HNSW는 긴 간선을 상위 계층으로, 짧은 간선을 하위 계층으로 분리해 검색이 항상 "긴 걸음부터 짧은 걸음 순으로" 진행되게 만들었습니다.

3. 계층 구조: skip list와 같은 원리

HNSW의 이름에서 Hierarchical은 그래프를 여러 계층으로 쌓는다는 뜻입니다. 원리는 정렬된 연결 리스트를 빠르게 검색하는 skip list와 같습니다. skip list는 모든 원소가 있는 맨 아래 줄 위에, 원소를 절반씩 건너뛴 "급행선"을 여러 줄 올립니다. 검색은 맨 위 급행선에서 큰 걸음으로 이동하다가, 더 못 가면 한 줄 내려와 작은 걸음으로 이동합니다.

HNSW는 노드마다 "최고 레벨" l을 무작위로 뽑아, 그 노드를 0계층부터 l계층까지 모든 계층에 넣습니다. 레벨은 지수 분포에서 뽑습니다.

l = floor( −ln U(0,1) × m_L ),   m_L = 1 / ln M      # P(l ≥ k) = M^−k

M=16이면 전체 노드의 1/16이 1계층 이상에, 1/256이 2계층 이상에 들어갑니다. 위로 갈수록 노드가 M분의 1로 줄어드는 것이 skip list의 "절반씩 건너뛰기"에 해당합니다. 계층 수는 약 log_M N이고, 최고 계층에는 노드가 몇 개뿐이라 그중 하나가 진입점(entry point)이 됩니다.

검색은 진입점에서 시작해 최고 계층부터 내려옵니다. 각 상위 계층에서는 후보 하나만 들고 탐욕 검색을 하고(큰 걸음), 더 가까운 이웃이 없으면 그 노드를 다음 계층의 시작점으로 삼습니다. 0계층에 도착하면 후보 여러 개를 들고 정밀하게 검색합니다(5절).

방문 표시

검색 한 번 동안 같은 노드를 두 번 확장하지 않도록 방문 여부를 기록해야 합니다. 노드마다 불리언 배열을 두고 검색마다 0으로 지우면 N에 비례하는 비용이 듭니다. hnswlib는 uint16 배열과 태그 값 curV를 씁니다. 검색을 시작할 때 curV를 1 올리고, visited[id] == curV이면 이번 검색에서 방문한 노드입니다. 태그가 65,535를 넘어 0으로 돌아올 때만 배열을 지웁니다. 동시에 실행되는 검색 수만큼 배열을 풀에서 빌려 씁니다.

5. 검색 알고리즘 전체

원 논문의 알고리즘 번호로는 K-NN-SEARCH(Alg. 5)가 SEARCH-LAYER(Alg. 2)를 호출하는 구조입니다. 3절의 그림 3이 이 과정을 보여 줍니다.

KNN_SEARCH(q, k, ef):
    ep = enterpoint
    for l = maxlevel down to 1:
        ep = SEARCH_LAYER(q, ep, ef=1, l)[0]        # 후보 1개 = 탐욕 검색
    W = SEARCH_LAYER(q, ep, max(ef, k), 0)          # 0계층에서만 후보 ef개
    return k nearest of W

SEARCH_LAYER(q, ep, ef, l):
    visited = {ep}
    C = {ep}                                   # 확장 후보. 최소 힙: 가장 가까운 것이 위
    W = {ep}                                   # 결과 후보. 최대 힙: 가장 먼 것이 위, 크기 ≤ ef
    while C ≠ ∅:
        c = C.pop_nearest()
        f = W.farthest()
        if dist(q, c) > dist(q, f): break      # 가장 가까운 후보도 결과의 최악보다 멀면 종료
        for n in links(c, l):
            if n ∈ visited: continue
            visited ∪= {n}
            f = W.farthest()
            if dist(q, n) < dist(q, f) or |W| < ef:
                C.push(n); W.push(n)
                if |W| > ef: W.pop_farthest()
    return W

SEARCH_LAYER는 후보 ef개를 동시에 추적하는 빔 검색(beam search)입니다. ef=1이면 탐욕 검색과 같고, ef가 커질수록 지역 최솟값에 빠질 확률이 줄어 재현율이 오릅니다. 아래 표는 그림 3의 0계층에서 ef=3으로 실행한 과정입니다. 괄호 안은 q까지의 거리입니다.

이웃 선택 휴리스틱

삽입할 때 후보 ef_construction개 중 M개를 골라 간선으로 삼아야 합니다. 가장 가까운 M개를 고르는 것이 자연스러워 보이지만, 그러면 간선이 한 방향 군집에 몰려 2절의 첫 번째 성질(어디로든 갈 수 있음)이 깨집니다. 원 논문의 Algorithm 4는 다음 규칙으로 방향이 다양한 이웃을 고릅니다.

SELECT_NEIGHBORS_HEURISTIC(q, C, M):      # C: 후보, q에 가까운 순서로 본다
    R = []
    for c in C sorted by dist(q, c):
        if |R| ≥ M: break
        if ∀ r ∈ R: dist(r, c) ≥ dist(q, c): R.append(c)    # 이미 고른 r이 c에 더 가까우면 c는 버림
    return R

1부 요약. HNSW는 (1) 근접 그래프 위의 탐욕 검색을 (2) skip list처럼 계층화해 경로 길이를 log N으로 줄이고, (3) 이웃 선택 휴리스틱으로 그래프의 항행 가능성을 지킵니다. 자료구조는 노드당 고정 크기 레코드 하나와 상위 계층 블록이 전부입니다. 2부에서는 이 구조를 온라인으로 고치는 연산을 다룹니다.

6. 삽입 addPointWithLevel · mutuallyConnectNewElement

새 노드의 최고 레벨을 무작위로 뽑은 뒤, 그 레벨보다 높은 계층에서는 탐욕 검색으로 진입점을 좁히고, 그 레벨부터 0계층까지는 빔 검색으로 후보를 모아 양방향 간선을 만듭니다. 5절의 SEARCH_LAYER와 SELECT_NEIGHBORS_HEURISTIC을 그대로 씁니다.

addPoint(x, label):
    # label이 이미 있으면 삽입이 아니라 값 갱신으로 분기한다 (8절)
    if label in label_lookup: return updatePoint(x, label_lookup[label])

    c  = cur_element_count++                  # 내부 ID는 증가만 하는 일련번호
    lc = floor( −ln U(0,1) / ln M )           # P(lc ≥ l) = M^−l
    record[c] = { links: ∅, vector: x, label }
    ep = enterpoint

    # (1) 탐욕 하강: 새 노드가 없는 상위 계층
    for l = maxlevel down to lc+1:
        ep = greedy(x, ep, l)

    # (2) 계층별 연결: 새 노드가 존재하는 계층
    for l = min(lc, maxlevel) down to 0:
        W = searchLayer(x, ep, ef_construction, l)
        if deleted(enterpoint): W ∪= { enterpoint }        # 삭제된 진입점도 강제로 연결
        N = selectNeighbors(W, M)                        # 최대 M개
        links(c, l) = N
        for n in N:                                       # 역방향 간선
            if |links(n, l)| < Mmax(l):  links(n, l).append(c)
            else: links(n, l) = selectNeighbors(links(n, l) ∪ {c}, Mmax(l))   # 꽉 찼으면 재선택
        ep = nearest(N)                                   # 다음 계층의 진입점

    if lc > maxlevel: enterpoint = c; maxlevel = lc       # Mmax(0) = 2M, Mmax(l≥1) = M


greedy(x, ep, l):                                     # = SEARCH_LAYER(x, ep, 1, l)
    repeat until no change:
        for n in links(ep, l):
            if dist(x, n) < dist(x, ep): ep = n
    return ep

searchLayer(x, ep, ef, l):                             # 5절 SEARCH_LAYER + 삭제 처리
    C = {ep}; W = {ep}; visited = {ep}
    while C ≠ ∅:
        c = C.pop_nearest()
        if dist(x, c) > max_dist(W) and |W| == ef: break
        for n in links(c, l):
            if n ∈ visited: continue
            visited ∪= {n}
            if |W| < ef or dist(x, n) < max_dist(W):
                C.push(n)                                 # 삭제된 노드도 확장은 한다
                if not deleted(n): W.push(n)              # 결과에는 넣지 않는다
                if |W| > ef: W.pop_farthest()
    return W

selectNeighbors(W, M):                                # 5절 휴리스틱. extend/keepPruned 없음
    if |W| < M: return W                                  # M개 미만이면 가지치기 없음
    R = []
    for c in W sorted by dist(x, c):
        if |R| ≥ M: break
        if ∀ r ∈ R: dist(r, c) ≥ dist(x, c): R.append(c)
    return R

주의할 점. 새 노드는 0계층에서도 처음에 M개까지만 연결하고 나머지 M개 자리는 이후 삽입되는 노드가 역방향 간선으로 채웁니다. 역방향 간선 재선택에서 q가 탈락하면 간선은 q → n 한 방향으로만 남습니다. 탈락한 기존 간선을 되살리는 keepPrunedConnections는 구현되어 있지 않아, 어떤 노드가 들어오는 간선을 모두 잃을 수도 있습니다.

7. 삭제 markDelete · 논리적 삭제

삭제는 그래프를 건드리지 않습니다. 레코드의 플래그 한 비트를 켜고 카운터를 올리는 것이 전부이며, 검색 쪽에서 그 노드를 결과에서만 걸러냅니다.

markDelete(label):
    id = label_lookup[label]                  # 매핑은 지우지 않는다
    flag(id) |= DELETE_MARK                   # 레코드의 세 번째 바이트, bit0
    num_deleted++
    if allow_replace_deleted: deleted_elements ∪= {id}    # 9절에서 재사용할 슬롯 집합
    # 간선, 벡터, 레벨, 진입점은 모두 그대로 둔다. 되돌리려면 unmarkDelete.

searchKnn(q, k):                                # 삭제가 검색에 미치는 영향
    ep = enterpoint                           # 진입점이 삭제돼도 교체하지 않는다
    for l = maxlevel down to 1: ep = greedy(q, ep, l)      # 삭제 여부를 보지 않는다
    if num_deleted == 0: W = searchLayer<bare>(q, ep, max(ef, k), 0)   # 삭제 확인을 컴파일 시점에 제거한 빠른 경로
    else:                W = searchLayer<checked>(q, ep, max(ef, k), 0) # 후보마다 flag 확인, 결과에서만 제외
    return k nearest of W

주의할 점. 삭제가 한 건이라도 생기면 모든 쿼리가 삭제 확인이 들어간 느린 경로로 바뀝니다. 삭제된 노드는 이웃의 차수 한 자리를 계속 차지하고, 메모리는 회수되지 않으며 cur_element_count도 줄지 않습니다. 물리 삭제와 압축은 없고, 메모리를 되찾는 유일한 수단은 9절의 슬롯 재사용입니다.

8. 값 갱신 updatePoint · repairConnectionsForUpdate

이미 있는 label로 addPoint를 호출하면 노드를 새로 만들지 않고 벡터를 덮어쓴 뒤 두 단계로 간선을 고칩니다. 먼저 갱신된 노드가 가리키던 이웃들이 자기 이웃 목록을 다시 고르고, 그다음 갱신된 노드를 새 위치에서 처음 삽입하듯 다시 연결합니다.

updatePoint(x_new, id):
    vector(id) = x_new                        # 잠금 없이 덮어쓴다. 동시 검색은 섞인 값을 읽을 수 있다

    # (1) 기존 이웃들의 간선 재선택. 레벨은 다시 뽑지 않고 그대로 둔다
    for l = 0 .. level(id):
        N1 = links(id, l)                     # id가 가리키는 1-hop 이웃만. id를 가리키기만 하는 노드는 모름
        C  = {id} ∪ N1 ∪ ⋃_{n ∈ N1} links(n, l)                # 2-hop 후보 집합 (최대 1+2M+4M² 개)
        for n in N1:
            K = C \ {n} 중 n에 가까운 min(ef_construction, |C|−1)개
            links(n, l) = selectNeighbors(K, Mmax(l))         # n의 리스트를 통째로 교체

    # (2) id를 새 위치에 다시 연결 (삽입의 (1)(2)단계와 같다)
    repairConnections(x_new, id)

repairConnections(x, id):
    ep = enterpoint
    for l = maxlevel down to level(id)+1: ep = greedy(x, ep, l)
    for l = level(id) down to 0:
        W = searchLayer(x, ep, ef_construction, l) \ {id}     # 자기 자신 제외 (self-loop 방지)
        if W == ∅: continue
        N = selectNeighbors(W, M)
        links(id, l) = N                                      # 덮어쓰기 (isUpdate=true)
        for n in N:
            if id ∈ links(n, l): continue                     # 이미 가리키면 건너뜀
            append or reselect as in insertion
        ep = nearest(N)

비용. M=16이면 0계층의 2-hop 후보가 최대 약 1,057개이고, 이웃 32개마다 이 후보 전체와 거리를 계산하므로 (1)단계만 약 3.4만 번의 거리 계산이 듭니다. 실험에서 값 갱신은 신규 삽입보다 점당 약 5배 느렸습니다. updateNeighborProbability를 1 미만으로 주면 재선택할 이웃을 표본으로 줄일 수 있지만, 라이브러리의 공개 API는 항상 1.0을 넘깁니다.

9. 삭제 슬롯 재사용 addPoint(…, replace_deleted=true)

생성자에서 allow_replace_deleted=true를 켰을 때만 동작합니다. 삭제된 노드의 슬롯을 하나 꺼내 label과 벡터를 새 점의 것으로 바꾼 뒤, 8절의 값 갱신을 그대로 실행합니다. 기존 레벨과 간선을 물려받으므로 그래프 수선도 값 갱신과 같습니다.

addPoint(x, label, replace_deleted=true):
    id = deleted_elements.pop_any()           # unordered_set::begin(). 비어 있으면 일반 삽입으로
    if id == none: return addPoint(x, label)

    old = label_of(id)
    label_of(id) = label                      # 레코드의 label 필드
    label_lookup.erase(old); label_lookup[label] = id
    flag(id) &= ~DELETE_MARK; num_deleted−−   # 삭제 표시 해제
    updatePoint(x, id)                        # 벡터 덮어쓰기 + (1) 이웃 재선택 + (2) 재연결
    # 잠금은 새 label 기준으로만 잡는다. 같은 순간 old label로 unmarkDelete를 부르면 경쟁 상태가 된다.

주의할 점. 어느 슬롯을 재사용할지는 해시 집합의 순서에 따라 정해지므로, 새 점과 전혀 무관한 위치의 슬롯을 받을 수 있습니다. 그 슬롯의 옛 이웃들이 새 점을 가리키는 단방향 간선이 남는 것은 값 갱신과 같은 한계입니다. 그래도 전체의 110%를 교체한 실험에서 recall@10은 ef≥50에서 새로 만든 인덱스와 0.002 이내였습니다.
